完整图每轮包含 `pins.tsv`、`vertices.tsv`、`edges.tsv`、`arc_delays.tsv`、`slews.tsv`、`boundary_paths.tsv`、`boundary_edges.tsv`、`manifest.tsv`。三锁存器每轮为 **35 个引脚、35 个顶点、40 条边、77 条时序弧、4 条边界边**。

导出采用当前工况下固定 GBA 弧权重；顶点 slew 不是逐条输入弧单独计算的输出 slew。组合段排除 latch 自身 DQ/CQ、时钟 latency 及外部 IO delay，分别保存最短和最长见证。没有进行逐路径重新表征或布尔可敏化证明。

日志记录 Howard、YTO、LP 周期均约 3.541155 ns，两项与 LP 的周期差为零。候选保留 IO 与工况后，由新的 OpenSTA 进程读取验证。两轮图的结构和组合边界值相同；时钟偏移改变不必然改变固定工况的组合弧权重。

结论仅为**当前报告范围内的理想时钟候选可行性**。10 ns 未被证明是最优零偏斜基线，不能直接计算为 CSS 频率收益；零 setup 裕量不能代表实现余量。单条脉宽摘要也不能代替所有实例的逐项签核。

归档保留执行输入、约束快照、工具版本、求解器参数/路径/哈希、日志和四份图像。运行副本中的 `examples/tiny_sky130` 路径保持原样，不因源案例改名而重写历史文件或哈希。

## 计数器：已形成流程，但实际运行未通过

[`examples/counter/`](../../examples/counter/) 使用四个 `dlrtn_1` 和四个 `dlrtp_1`。新增 STA 脚本动态识别实例与 GATE_N/GATE，保留 RESET_B、recovery/removal、脉宽及 reset→Q min/max 报告。流程不通过 false path 或固定复位值隐藏检查。

真实尝试位于 [`examples/counter/run_counter_01/`](../../examples/counter/run_counter_01/)，已保存映射网表和 **82 份 `.rpt`**。日志末尾为：

```text
Error: run_sta.tcl, 93 Indistinguishable parallel timing edges: v1 v3 combinational {} {} {}
```

因此 `flow_status.json` 保持 **incomplete**，没有完整图完成标记或成功流程检查。该计数器不能记作完整 STA/图导出验收通过；失败材料原样归档。

优化仍为 **unsupported**：当前 v3 转换器、时序模型和 SDC 导出不能完整表达双极性、复位、多 IO 和反馈。不生成假的优化输入或候选 SDC；此限制不代表 Howard 算法本身不能处理含环约束图。
